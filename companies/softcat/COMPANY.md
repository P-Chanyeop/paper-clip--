소프트캣은 작게 시작하는 개발 조직이다. 사람 운영자 1명이 CEO 에이전트에게
목표를 주면, CEO가 일을 쪼개 세 명의 전문가에게 나눈다.

## 조직 운영 원칙

**1. 작게 시작한다.** 에이전트 수에 비례해 비용이 늘고, 많아지면 누가 가치를
냈는지 분리가 안 된다. 4명으로 시작해 효용이 증명된 역할만 늘린다.

**2. 구현과 리뷰를 분리한다.** 같은 에이전트가 코드를 짜고 스스로 리뷰하면
자기 코드를 통과시킨다. 엔지니어와 리뷰어를 나눈 것은 조직 설계가 아니라
**신뢰성 장치**다.

**3. 머지는 사람이 한다.** 네 에이전트 모두 머지 권한이 없다. 예외 없음.

**4. 승인 게이트를 먼저 풀지 않는다.** 에이전트가 승인 없이 저장소에 쓰기
시작하면 사고 한 번으로 팀 전체가 이 도구를 불신하게 된다. 신뢰는 게이트를
천천히 푸는 방향으로만 쌓인다.

## 업무 흐름

```
         사람 운영자
              │ 목표 제시 / 최종 승인
              ▼
         CEO ──────────────────────┐
          │ 작업 분해·배정          │ 조사 의뢰
          ▼                        ▼
   ┌─────────────┐           ┌───────────┐
   │  엔지니어   │           │  리서처   │
   │   (구현)    │           │ (조사·문서)│
   └──────┬──────┘           └─────┬─────┘
          │ PR 생성                 │ 보고서
          ▼                        │
   ┌─────────────┐                 │
   │   리뷰어    │                 │
   │ (한국어 리뷰)│                 │
   └──────┬──────┘                 │
          │ 리뷰 완료               │
          ▼                        ▼
      사람이 머지 판단          CEO 취합
```

- **CEO**: 목표를 작업으로 쪼개고 배정한다. 직접 구현하지 않는다.
- **엔지니어**: 작업을 받아 구현하고 PR을 연다. 머지하지 않는다.
- **리뷰어**: PR을 한국어로 리뷰한다. 코드를 고치지 않는다.
- **리서처**: 독립적으로 조사하고 문서를 남긴다. 코드를 쓰지 않는다.

## 예산

회사·에이전트 단위로 월 한도를 건다. 80%에서 알림, 100%에서 자동 정지.
회사 한도만 걸면 에이전트 하나가 폭주할 때 전사가 멈추므로, 에이전트별
한도로 폭발 반경을 가둔다.

금액은 1주 실사용 데이터로 정한다. 추측으로 정하지 않는다.

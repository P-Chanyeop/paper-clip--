# 리뷰 체크리스트

변경 유형별로 **실제로 깨진 적이 있는 것들**만 모았다.
일반론은 넣지 않았다. 체크리스트가 길면 아무도 안 본다.

## 모든 PR

- [ ] 변경된 함수의 **호출자를 전부 확인**했는가? (호출자를 모르면 영향도 판단 불가)
- [ ] 에러 경로가 있는가? 실패하면 어떻게 되는가?
- [ ] 새 코드에 테스트가 있는가? 없다면 왜 없어도 되는가?
- [ ] 기존 테스트가 깨지지 않는가?

## 비동기 / 동시성

- [ ] `await` 누락 — 가장 흔한 실제 버그
- [ ] Promise 거부가 처리되지 않는 경로
- [ ] 경쟁 조건: 같은 자원을 두 경로가 동시에 쓰는가?
- [ ] 트랜잭션 경계가 맞는가? 중간 실패 시 일관성이 유지되는가?

## 데이터 / DB

- [ ] 마이그레이션이 **되돌릴 수 있는가?**
- [ ] 인덱스 없는 컬럼으로 조회하는가? (데이터가 쌓이면 터진다)
- [ ] NULL 처리. 기존 행은 어떻게 되는가?
- [ ] 돈·수량은 정수(cents)인가? 부동소수점이면 🔴

## 보안

- [ ] 사용자 입력이 쿼리·셸·경로에 그대로 들어가는가?
- [ ] 비밀정보가 로그·에러 메시지·응답에 노출되는가?
- [ ] 권한 검사가 **모든** 진입점에 있는가? (한 곳만 빠져도 의미 없다)
- [ ] 테넌트 경계: 다른 회사 데이터에 접근 가능한가?

## 비용 (Paperclip 특수 사항)

- [ ] 에이전트 실행 비용이 원장(`cost_events`)에 기록되는가?
- [ ] 예산 초과 시 정지 경로를 우회하지 않는가?
- [ ] 재시도 루프에 상한이 있는가? (무한 재시도 = 무한 비용)

## 프런트엔드 (이 저장소)

- [ ] 하드코딩된 색상(hex)·간격(px)이 있는가? → `DESIGN.md` 원칙 2 위반
- [ ] Tailwind 팔레트 클래스(`bg-red-500`)를 새로 추가했는가? → 토큰을 쓸 것
- [ ] 새 컴포넌트가 기존 것과 중복되는가? → `DESIGN.md` 원칙 1
- [ ] `*.production.tsx` 쌍 파일이 있는데 한쪽만 고쳤는가?
- [ ] 상태 표현이 기존 상태 토큰 체계를 따르는가? → `DESIGN.md` 원칙 5

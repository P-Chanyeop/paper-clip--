## 배경 (검증된 사실)

리서처의 저장소 파악 보고서가 지적했고, 사람이 다시 확인했다:
우리 포크가 추가한 디렉터리가 저장소 규약 어디에도 없다.

- `companies/` — 회사 패키지 (agentcompanies/v1)
- `mvp/` — MVP 설계 문서
- `skills/kr-*` — 한국어 스킬
- `scripts/kr/` — 한국어화 도구

`AGENTS.md`의 Repo Map에 이 넷이 없다. 그래서 **리뷰어가 이 영역의 PR을
판단할 기준이 없다.** 이 작업은 리뷰어의 기준을 만드는 일이다.

## 할 일

각 디렉터리에 대해 적는다:
1. 무엇이 들어가는가
2. 무엇이 들어가면 안 되는가
3. 바꿀 때 지켜야 할 것 (예: `companies/softcat/skills/kr-code-review/`는
   `skills/kr-code-review/`와 내용이 같아야 한다)
4. 검증 명령

## 제약 — 반드시 지킬 것

- **업스트림 파일 수정을 최소화한다.** 이 저장소는 업스트림(paperclipai/paperclip)을
  주기적으로 머지한다. `AGENTS.md`를 크게 고치면 매번 충돌한다.
  → 규약 본문은 **새 파일**에 쓰고, 업스트림 파일에는 **한 줄 포인터까지만** 허용한다.
- 저장소 규약(`AGENTS.md` §5-4)에 따라 전략 문서를 통째로 바꾸지 않는다.

## 산출물

- 새 브랜치에서 작업하고 **PR을 연다.** 머지하지 않는다.
- PR 본문에 무엇을 왜 바꿨는지, 리뷰어가 어떻게 확인할 수 있는지 적는다.

## 완료 기준

PR이 열렸고, 다음 작업(리뷰)이 그 PR을 대상으로 시작될 수 있는 상태.

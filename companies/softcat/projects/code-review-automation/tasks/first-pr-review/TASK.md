실제 PR 하나를 `kr-code-review` 스킬대로 리뷰한다. **시험 운영이다.**

## 순서

1. 대상 PR을 하나 고른다 (없으면 최근 머지된 PR로 연습)
2. 스킬의 절차를 그대로 따른다 — 맥락 읽기 → diff → 분류 → **검증** → 코멘트
3. 요약 코멘트에 리뷰하지 못한 범위를 명시한다

## 이 작업의 진짜 목적

리뷰를 다는 게 아니라 **스킬이 실제로 동작하는지 확인하는 것**이다.
그래서 마지막에 반드시 다음을 작업 댓글로 남겨라:

- 스킬 지시문 중 **모호했던 부분**
- 판단이 어려웠던 지적과 그 이유
- 체크리스트에 **추가되어야 할 항목**

이 피드백이 없으면 시험 운영을 한 의미가 없다.

## 하지 말 것

- 지적 개수를 늘리려 하지 마라. 확신 없으면 남기지 않는 게 맞다.
- 코드를 고치지 마라.
